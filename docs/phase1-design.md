# 第一阶段设计与开发任务

## 阶段目标及交付边界

交付一条可在普通 Windows 笔记本上运行、可注入故障、可留痕的离线处理链；随后在同一契约下替换真实只读适配器。相机和机械臂可以分别接入，无需等两台设备同时可用。

尚未确认的现场参数：A1 控制器/服务端版本与连接方式、Gemini 固件与 SDK wheel、RGB-D 对齐方式、真实安装变换与工具偏置。它们只阻塞对应硬件任务，不阻塞 Mock 开发。不要将显示接口形状作为控制协议证据。

## 模块边界

| 模块 | 输入 → 输出 | 职责与禁止越界 |
|---|---|---|
| devices | 厂商状态/帧 → 统一 Frame、RobotState | 连接、超时、时间归一化、单位转换、关闭；不识别目标，不自动使能或运动 |
| vision | 已对齐 RGB-D、内参、检测目标 → 相机坐标点和质量信息 | 像素/深度有效性、去畸变、靶标定位；不调用机器人 SDK |
| calibration | 多姿态配对观测 → T_E_C 与质量报告 | 手眼求解、独立留出验证、版本与适用设备记录；不能把单位矩阵当真实标定 |
| geometry | 有方向标记的 SE(3) 与点 → 目标坐标 | 统一单位和坐标链；拒绝非法旋转/非有限数 |
| safety | 新鲜状态、候选目标、质量、标定状态 → 允许预览/拒绝及原因 | 超时、失联、边界与故障锁存；上层不得绕过；软件检查不替代硬件急停 |
| recording | 配置、原始观测、算法结果、拒绝原因 → 可追溯记录 | 独立 run_id、UTC、单调时间、数据来源、标定版本；记录失败须停止后续处理 |
| app | 配置与模块接口 → 一次处理流程 | 编排与异常收敛；算法不直接散落在 CLI 中 |

当前单点 Frame 是最小接口。真实采集前增设 RGBDFrame：RGB/Depth 文件引用、各自 frame_id/设备时间戳、接收时刻、曝光区间（可得时）、分辨率、内参/畸变、深度比例、对齐目标及流配置。不得把单点示例称为完整 RGB-D 采集器。

## 坐标和时间契约

统一右手系，内部长度为米、角度为弧度，列向量；SDK 的 mm/deg 只在适配器边界转换。`T_A_B` 表示把 B 系坐标变到 A 系：`p_A=T_A_B @ p_B`。

- B：机械臂基座；E：机械臂末端法兰；C：相机光学坐标系；M：标定板/外部靶标；T：工具尖端。
- SDK 的末端位姿若实际是 TCP，必须先说明 TCP 与法兰的关系，不能直接标为 T_B_E。
- 光学系采用 x 向右、y 向下、z 向前；真实 SDK 若不同，适配器显式转换。
- `p_B = T_B_E @ T_E_C @ p_C`。
- 靶标位姿链：`T_B_M = T_B_E @ T_E_C @ T_C_M`。
- 工具尖端：`T_B_T = T_B_E @ T_E_T`；虚拟快换必须同时更新工具 ID 和对应偏置。
- MRI/图谱与实体头模配准是后续独立任务，不能把体素坐标直接当机器人坐标。

时间戳使用主机单调时钟比较新鲜度；UTC 仅用于追溯。相机设备时钟须映射到主机时钟并记录映射误差；收到帧的时刻不等于曝光时刻。示例同步窗口 50 ms、新鲜度 200 ms 只服务合成测试，不是实机合格阈值。真实标定先采用“机械臂停止、确认稳定、配对拍摄”的采集流程，避免用软件时间接近掩盖曝光差异。

## 虚拟数据验证

| 场景 | 数据构造 | 验收 |
|---|---|---|
| 正常坐标链（已实现） | 像素 (320,240)，fx=fy=500，主点 (320,240)，z=0.5 m；末端平移 (0.1,0.2,0.3)，相机安装平移 (0.02,0,0.05) | 基座点 (0.12,0.2,0.85)，误差 <=1e-12 m，仅预览 |
| 方向错误（已实现部分） | 90° 旋转加平移、逆变换、反射矩阵 | 已知点正反变换正确，反射拒绝；后续加误用转置和 mm/m 用例 |
| 失效与恢复（已实现） | 无效帧、过期/未来时间、失联、不同步、越界、NaN、关节数错误 | 全部拒绝；恢复数据不解除故障锁存，显式复位后再检查 |
| 事件回放（已实现） | JSONL 序列化后重读 | 保存事件不变，回放零设备调用 |
| 完整离线视觉（待实现） | 合成 ChArUco 图、已知内参/畸变、深度空洞与噪声，固定随机种子 215 | 与真值比较像素/三维误差，区分检测失败和深度无效；输出质量而非只输出坐标 |
| 手眼真值恢复（待实现） | 多组非共轴旋转/平移；已知 X=T_E_C、Y=T_B_M，生成 C_i=inv(X) inv(G_i) Y | 仅训练组求解，在留出姿态检查 G_i X C_i 的一致性；无噪声目标平移 <=1e-6 m、旋转 <=1e-6 rad；这是数值测试目标 |
| 手眼退化（待实现） | 仅平移、单轴旋转、重复姿态、错误配对 | 识别退化或低置信，不产出“通过”结论；有噪声时报告误差分布 |
| 完整日志与重算（待实现） | 保存帧文件、关节、变换、配置、Git SHA、SDK/固件及校验和 | 同一输入可重算结果；日志/磁盘失败时终止，不输出成功 |

手眼方程可由 `G_i X C_i = Y` 得到：`A=inv(G_j) G_i`、`B=C_j inv(C_i)`，满足 AX=XB。OpenCV 求解器输入方向必须按其 API 文档核对；用上述真值生成器确认结果，不能只看训练残差。真实标定需采集约 20–30 个有不同旋转轴的稳定姿态，并保留独立验证姿态；不能将合成误差当实机定位精度。

## 状态与故障策略

目标状态：DISCONNECTED → CONNECTED_READONLY → COLLECTING → PREVIEW_READY；任意采集/计算/记录错误进入 FAULT，停止产生新的有效预览。用户确认复位后回到只读检查，再采集新鲜数据。当前 Interlock 实现锁存与显式复位；完整连接生命周期状态机留待 P2。

重新连接不等于恢复可用：须核对设备身份、时间新鲜度、标定版本与质量。真实控制在后续阶段单独设计执行入口，并在发送当刻重新检查状态；当前位置到目标点的路径、关节限位、碰撞、速度、工具与硬件急停均未由当前点坐标边界检查覆盖。
